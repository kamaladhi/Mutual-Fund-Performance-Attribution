# Combined architecture

## Design
- `app.py` is a presentation layer. It reads each market's saved `data/processed/final_evaluation.csv` and
  `data/raw/screening_metadata.json` through `combined_data.py` and never estimates anything.
- `combined_data.py` is the single data layer (no Streamlit import). The dashboard, `scripts/build_combined_results.py` and the tests all
  use it, so the numbers on screen, in the export and in the checks cannot drift apart. It also refuses to present the markets as
  comparable if they were classified under different rule versions or if a class label is not in the shared vocabulary.
- `markets/india/` and `markets/usa/` are self-contained analysis projects (own `src`, data, tests, documentation and original
  dashboard). They are kept as separate packages because both use module names such as `src.evaluator`.
- **One rule set.** The evidence rules (flags, scores, classes, explanations, thresholds) are identical in
  `markets/india/src/evaluator.py` and `markets/usa/src/evaluator.py`, and the persistence and statistics helpers are identical too.
  `tests/test_rule_parity.py` compares their syntax trees, so a rule cannot be changed in one market only. The USA evaluator additionally
  derives three bootstrap columns and two factor columns from its saved results (it pre-dates them) exactly as the India engine defines
  them; no statistic is re-estimated.
- `data/combined_results.csv` is a convenience export generated by `scripts/build_combined_results.py` (`--check` verifies it).

## Refresh flow
1. Run the relevant market's pipeline from inside its folder (India: `python run_pipeline.py`; USA: `python -m src.persistence`
   then `python -m src.evaluator .`).
2. Confirm `data/processed/final_evaluation.csv` was updated and carries the same `evaluation_version` in both markets.
3. `python scripts/build_combined_results.py`, then refresh the dashboard (it detects changed files).
4. Run the three test suites (see the root README).

## Non-goals
The combined dashboard does not estimate alpha, perform bootstrap resampling, reconcile factor definitions or validate model
assumptions. Those responsibilities remain with each market's pipeline; the correctness of their outputs is covered by the tests
(including an independent statsmodels cross-check in `tests/test_independent_numerics.py`).
